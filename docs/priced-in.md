# priced-in 判定：这个信号是不是已经被市场消化了

## 要解决的问题

信号是用**日线**算出来的。这带来一个很real的风险：

> 你看到一条"关键位突破"的绿灯，但那个突破其实是**三天前**发生的，
> 现价已经比入场位高出 8%，群里也早就没人聊了——
> 这时候进场就是**追高**，市场早把这个信息 price in 了。

方法论里对应的是"**二阶思考**"那一条：
*表面消息 ≠ 交易方向，永远想"这条消息的传导路径和已被 price in 的程度"*。

所以每张信号卡都会跑一次"新鲜度体检"，代码在
[`src/signals.py`](../src/signals.py) 的 `staleness()`。

---

## priced-in 标签一览

| 标签 | 触发条件 | 默认阈值 | 含义 | 会降级 🟢→🟡？ |
|---|---|---|---|---|
| **`extended`** | 现价越过入场位太多 | `> 3%`（**按杠杆倍数放大**）| 已经涨过头了，你是在追高 | ✅ 会 |
| **`stale_breakout`** | 突破发生在几天前 | `≥ 2` 个交易日 | 旧突破，肉多半被吃过了 | ✅ 会 |
| **`stale_chat`** | 群里最后一次提到该票距今太久 | `> 180` 分钟 | 讨论已经冷了，热度过去了 | ✅ 会 |
| **`capped`** | 入场位上方紧贴一堵 call wall | `≤ 1.5%` | 上方有"盖子"，突破可能就停在那 | ✅ 会 |
| **`earnings_consumed`** | 财报催化距今太久 | `> 3` 天 | 旧闻，市场消化完了 | ❌ **只做展示**（原因见下）|

阈值全部集中在 [`src/config.py`](../src/config.py)，随时可调：

```python
EXTENSION_PCT_MAX   = 3.0    # 追高阈值（会 × 杠杆倍数）
BREAKOUT_STALE_DAYS = 2      # 突破多久算旧
STALE_CHAT_MINUTES  = 180    # 聊天多久算冷
EARNINGS_STALE_DAYS = 3      # 财报多久算消化完
CALL_WALL_CAP_PCT   = 1.5    # call wall 多近算"盖子"
```

### 几个设计细节

**杠杆放大**：`extended` 的阈值是 `3% × 杠杆倍数`。3x ETP 日常就能波动 6-9%，
用同一把尺子量会误判成"追高"。

**聊天新鲜度从哪来**：`extract.last_mention_times()` 会按时间块扫描聊天记录，
记下每只票**最后一次被提到**的 UTC 时间，再和现在比。
这就是你最初提的那个需求——"信号可能是一天前的、早被 price in 了"。

**`capped` 来自期权**：`options.py` 算出 call wall（最大 call 未平仓量所在的行权价 = 上方阻力），
如果突破入场位就贴在它下面 1.5% 以内，说明上方有一堵墙。详见 [期权确认](./options.md)。

## 命中之后会怎样

### 1. 灯色降级（保守方向）

```
🟢 绿灯  +  命中任一 priced-in 标签   →   🟡 黄灯
```

**只降不升**：黄灯不会因为"很新鲜"被抬成绿灯，红灯也不动。
宁可错过，不可追高。

### 2. 推送里写清楚原因

信号卡会直接用中文告诉你为什么该谨慎：

```
⚠ Priced-in risk. The price is already 4.2% above the entry.
  The breakout is 2 days old.
  The group did not talk about it for 260 minutes.
  Maybe the market already knows this.
```

而不是只给你一个孤零零的 🟡。

## ⚠️ 一个重要的设计教训

`earnings_consumed` **不参与灯色降级**，只做展示。这是踩过坑之后改的：

早期版本把它也放进降级集合，结果是——Finnhub 返回的永远是"上一季"财报，
几乎每只个股都常驻这个标签，于是**任何**卡片的绿灯都被压成黄灯，
连"今天刚放量突破"的票也被无关的旧财报连累。
后果：08-17 到 08-29 期间 **1361 条信号，0 个绿灯**。

**正确做法**：过期的财报应该是**失去 A 档催化资格**（在 `detect()` 里降为 C 档背景），
而不是拿它去降级整张卡。这样：

- 只有旧财报、没别的 → 拿不到 A 档 → 🔴 红灯（正确）
- 新鲜突破 + 旧财报 → 突破仍是 A 档 → 🟢 绿灯（正确，突破才是理由）
- 旧突破 + 旧财报 → `stale_breakout` 降级 → 🟡 黄灯（正确）

> 教训：**过期的东西应该"不再加分"，而不是"额外扣分"**——
> 否则会误伤那些同时具备新鲜理由的标的。

## 简报侧的 priced-in 检查

除了信号卡，**脉搏简报**里也有一段独立的 priced-in 判断——
`prompts/pulse_summary.md` 要求模型对每个涉及价格/消息的话题回答：

- 市场是不是已经知道这个消息了？
- 消息出了但价格没按预期走 → 标 **second-order**（sell the news）
- "利空不跌"类观点 → 标 **needs more days**（一天不算数）

所以是**两层**：AI 判断"聊天里的消息"是否被消化，本地规则判断"价格信号"是否被消化。
