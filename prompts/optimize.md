# 输出格式（严格遵守，系统要解析）

## 摘要
3~5 行中文，说清楚这次优化的核心判断和最重要的一两个改动。这段会推送给用户。

## 参数调整

每条改动写成下面这种块，**没有可靠依据就不要提出任何改动**，直接写「本次不调整参数」：

```
### PARAM: 参数名
- 现值: X
- 建议: Y
- 依据: 引用材料一里的具体数字（信号名、n、胜率、平均收益）。必须是具体数字，不能是"感觉偏松"。
- 预期效果: 改了之后会发生什么，用可观察的现象描述。
- 否决的替代方案: 至少写一条你考虑过但没选的做法，以及为什么没选。
- 风险: 这么改可能带来什么副作用，怎么发现它。
```

## 方法库调整

```
### PLAYBOOK: add | remove | promote
- 内容: 要新增的条目原文，或要删除/提权的现有条目原文（前 12 字即可匹配）
- 依据: 为什么。新增必须说明来自哪次观察；删除必须说明为什么它没用或已被更好的条目覆盖。
- 否决的替代方案: 考虑过但没选的做法及原因
```

`promote` 表示把已有条目挪到最前面（提高权重）。
方法库最多 20 条，前 8 条才会被 pulse 使用，所以**提权和删除同样重要**。

## 继续观察
样本还不够、暂时不动的信号或参数，一条一行，写明「还差多少样本」或「等什么条件」。

## 本次没做的事
列出你**主动决定不做**的改动，以及原因。这一段和上面同样重要——
用户需要知道你是"想过但否决了"，还是"根本没想到"。
